# Janus DemiHead

**Статус: работа в процессе.** Сейчас оформлены границы проекта, архитектура и JSON-контракты. Рабочий сборщик телеметрии, адаптер Storj и замеры накладных расходов ещё не реализованы.

## Суть

DemiHead - локальный адаптер-наблюдатель. Он должен брать разрешённые операционной системой метрики уже работающего процесса, превращать их в проверяемые числовые сигналы и выдавать разные проекции общего состояния через «лица» Януса.

```text
чужой процесс
  -> пассивное наблюдение
  -> окно измерений
  -> нормализация
  -> проверка свежести и бюджета
  -> лица / выходы
```

Наблюдаемый процесс продолжает штатную работу и не требует интеграции с DemiHead. Это означает отсутствие вмешательства, а не скрытность: DemiHead не должен внедряться в процесс, читать его память, перехватывать секреты или обходить контроль системы.

## Что считается полезным числом

Не любой хеш или шум. Полезный сигнал должен иметь:

- понятный источник;
- формулу преобразования;
- время измерения;
- единицу или ограниченную шкалу;
- свежесть и доверие;
- версию алгоритма;
- измеренную стоимость самого наблюдения.

Если данных нет или они устарели, результат остаётся неизвестным. Ноль подставлять нельзя.

## Лица

Рабочая модель пока такая:

- `mirror` показывает нормализованное состояние;
- `steward` регулирует только частоту и нагрузку самого DemiHead;
- `registry` формирует ограниченные JSON-записи для анализа и мета-реестра.

Названия и состав лиц ещё можно изменить. Главное правило: все лица получают один общий кадр сигнала и не выдумывают разные версии исходной реальности.

## Первый прототип

Первый вертикальный срез должен наблюдать один выбранный процесс Windows, читать CPU, память и накопительные счётчики ввода-вывода, вычислять скорости и стабильность, писать JSON Lines и останавливать собственную активность при превышении бюджета.

Storj - первый кандидат для профильного адаптера. Сначала нужно точно определить форму запуска: нативный процесс, Docker-контейнер или другой вариант.
