# TACHYON-R3.4 — executable frozen neural model for custodian-only questions

**Research only. Not an independent blind experiment.** This extends R3.3 offline sealed challenge by connecting a question-only input to **real frozen Torch weights** from R3.1B, rather than accepting an arbitrary JSON of claimed model predictions.

## Security fix in R3.3 seal/score

The original R3.3 transport removed the `gold` field but copied arbitrary additional row keys. A malicious or accidental `answer_hint`, `solution_steps`, or nested key could have been leaked into the questions-only payload. R3.4 rejects unrecognized private row fields and uses an explicit allowlist: `case_id`, `category`, `family`, `question`, `source_url`. Each question-only JSON receives an immutable SHA-256 digest over its exact canonical contents, and the local score step refuses a prediction file whose `questions_sha256` differs from the original committed questions-only transport. None of this attests when the challenge was created; independent signature/timestamp remains mandatory.

## Actual frozen R31B inference (not a generated answer file)

`tachyon/r34_frozen_inference.py` verifies the entire checkpoint byte SHA-256 `b3b36dfb3e8c1d0d4a1ae1b867978cfa5f8f28d6768d1a42efac02a4d2e47f01` and loads it with `torch.load(weights_only=True,map_location='cpu')`. It checks model schema, family map, seed, dimensions and production HOLD before calling forward with one CPU thread. It never reads private gold answers or salt, runs an optimizer, makes web requests or updates model weights.

The candidate is a tiny scalar network with just two explicit training families. For the exact canonical SR proper-time or Born projector questions, and only if the family ID and input shape agree, the program may emit a dimensionless numeric prediction **from the network itself**. Other physics families, conceptual questions, OOD, unrecognized text and wrong input shapes cause `kind=abstain`. This is a routing/abstention safety policy, not generalized physics competence.

## Separate handoff protocol

An independent external custodian must FIRST seal a genuinely unseen 60+ question gold pack using the offline R3.3 CLI and secret salt. The custodian retains original private gold and salt. After the seal, only `questions_only.json` may reach an isolated, network-disabled inference host holding the exact R31B checkpoint. The host runs:

```bash
python -m tachyon.r34_frozen_inference \
  --questions-only /isolated/question_transport.json \
  --frozen-model /isolated/r31b_math_neural_research_only.pt \
  --predictions-out /isolated/frozen_predictions.json
```

The response consists only of case IDs, `kind`, numbers/units where applicable, transport SHA, candidate SHA, forward counts and HOLD flags. It contains no secret answers. The external custodian must independently timestamp and archive the actual output SHA before opening gold. They then run the R3.3 private score command on their own secured machine; conceptual scoring still requires independent expert review.

**Do not upload real hidden questions, correct answers, salts, custodian keys, passwords, or sensitive observations into GitHub Actions or Meta Registry.** The public GitHub test builds four wholly synthetic *development canaries* and downloads the original R31B checkpoint artifact. It verifies two real frozen numerical forward calls on familiar formulas, two refusals on unfamiliar topics, no retraining, SHA of model and questions, and no scientific/production promotion. The public canary is NOT a blinded test.

## Residual blockers

1. An actual independent researcher must take custody of unseen questions and their answer key; a reviewer or custodian signature and independent timestamp are not generated by this code.
2. R31B has never learned muon decay or battery electrochemistry; an out-of-family numeric test must abstain. Independent validation cannot award a generalization win for a safe refusal.
3. The protocol currently verifies file hashes and honest local behavior, but a malicious operator could fabricate an output or alter the test environment without an independently attested execution log. Add external trusted execution review or a custodian-controlled machine.
4. Real observed physics gains still need a genuinely new model trained on curator-approved, rights-checked physical measurements, prospective evaluation and strong baselines. No automatic promotion by a checksum or CI pass.
